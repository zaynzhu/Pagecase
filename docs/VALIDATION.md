# 页匣 · Pagecase 第一版验证计划

## 1. 验证原则

- 先用确定性模拟数据验证，再考虑真实集成。
- 当前用户的 Chrome 是禁止触碰的验收边界。
- 每个功能必须有可观察的通过条件，不能以“代码已经写完”代替验证。
- 无法验证的项目必须明确标为未验证，不以推断替代。

## 2. 自动化验证

### 2.1 Swift

必须通过：

```bash
swift build
swift test
swift build -c release
```

测试覆盖：

- schema v1 实时现场和快照解码
- 多窗口、命名组、未命名组、未分组标签和重复网址
- 标签组与网页顺序保持
- 原子写入成功与失败后旧文件保留
- 保存快照后实时现场变化不影响快照
- 搜索标题、域名、网址、组名和快照名
- 搜索不合并重复网址
- 导出与导入往返一致
- 损坏文件、未知 schema 和标识冲突
- 命令创建、领取、结果和超时
- 4MB Native Messaging 上限与长度前缀解析

### 2.2 Chrome 扩展

必须通过：

```bash
node --check extension/background.js
node --check extension/snapshot.js
node --test extension/tests/*.test.js
```

测试覆盖：

- 普通窗口捕获
- 无痕窗口过滤
- 非 `http/https` 页面过滤
- 标签组名称、颜色、折叠状态和顺序
- 未分组标签
- 相同网址保留多次
- 400ms 防抖只发送最后一次完整现场
- `focusTab` 只聚焦窗口与标签
- `openUrl` 每次只创建一个标签
- 未知命令被拒绝

## 3. 静态安全验证

在扩展目录执行禁止 API 扫描，以下内容必须零命中：

```text
tabs.remove
tabs.move
tabs.discard
tabs.group
tabs.ungroup
windows.remove
tabGroups.update
```

网络扫描必须确认不存在：

```text
fetch(
XMLHttpRequest
WebSocket
http://
https://
```

`manifest.json` 权限必须精确等于设计中的四项，不得出现通配 host 权限。

## 4. 模拟数据

固定夹具至少包含：

- 2 个浏览器来源
- 3 个窗口
- 5 个标签组，其中一个未命名、一个已折叠
- 24 个网页项
- 4 个未分组网页项
- 2 个完全相同的网址，位于不同标签组
- 固定、活动、播放声音和已丢弃状态各至少一个
- 2 个快照，其中一个来源离线

另外生成 500 个网页项的性能夹具。

## 5. 视觉验收

使用模拟数据启动 Release 应用，不连接 Chrome。至少检查：

- 浅色与深色模式
- `1080 × 700` 默认窗口
- `860 × 560` 最小窗口
- 现在、快照、设置和搜索状态
- 长标题、长网址、中文与英文混排
- 未命名标签组、空资料库、离线和数据过期
- 键盘焦点、`⌘K`、上下键、Return 与 Escape
- 减少动态效果和减少透明度

截图必须确认：

- 没有渐变、重阴影和大面积高饱和色
- 结构主要由排版、空白和 1px 分隔构成
- 彩色装订脊线清晰但不喧宾夺主
- 页面不是卡片墙
- 主要操作在首次看到时可以理解

## 6. 内存与 CPU

Release 应用加载 500 个网页项并空闲 60 秒后测量：

- 应用 RSS 目标不高于 80MB，验收上限 100MB
- Bridge RSS 目标不高于 25MB
- 应用空闲 CPU 平均不高于 1%
- 文件轮询与目录监听不得持续唤醒造成可见 CPU 抖动

如果超过目标但未超过上限，交付时记录实测值和后续优化方向；超过验收上限则第一版不能交付。

## 7. 打包验证

必须确认：

- `scripts/build-app.sh` 在仅安装 Command Line Tools 的环境成功
- `.app` 具备正确名称、标识、最低系统版本与图标
- Bridge 位于应用包内固定路径
- ad-hoc 签名验证通过
- 应用可从 Finder 或 `open` 启动
- 安装脚本在模拟目录生成合法 Native Messaging manifest
- 卸载脚本只删除精确的 Host manifest，不删除应用数据

真实 Chrome 扩展加载、Host 注册与标签定位不在本轮执行范围内，必须标记为“待用户授权的真实集成验证”。

## 8. 交付门槛

只有同时满足以下条件才可提交第一版：

1. Swift 与 Node 测试全部通过。
2. Release 应用构建和启动成功。
3. 禁止 API 与网络扫描零命中。
4. 视觉验收无阻断问题。
5. 内存和 CPU 未超过验收上限。
6. 当前 Chrome 未被读取或操作。
7. 所有未做的真实环境验证被明确列出。
