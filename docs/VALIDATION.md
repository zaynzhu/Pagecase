# 页匣 · Pagecase 0.6 验证计划

## 1. 验证原则

- 先用确定性模拟数据验证，再考虑真实集成。
- 当前用户的 Chrome 与 Safari 是禁止触碰的验收边界。
- 每个功能必须有可观察的通过条件，不能以“代码已经写完”代替验证。
- 无法验证的项目必须明确标为未验证，不以推断替代。

## 2. 自动化验证

### 2.1 Swift

必须通过：

```bash
swift build
swift test --enable-swift-testing --disable-xctest
swift run PagecaseCoreChecks
swift build -c release
```

当前仅安装 Command Line Tools 的机器缺少可正常枚举测试的 `xctest` 运行器；`swift test` 仍负责构建 Swift Testing 测试包，`PagecaseCoreChecks` 在本机实际执行同一组核心行为检查。完整 Xcode 环境仍保留 `Tests/PagecaseCoreTests` 供标准测试发现。

测试覆盖：

- schema v1 实时现场和快照解码
- 多窗口、命名组、未命名组、未分组标签和重复网址
- 标签组与网页顺序保持
- 原子写入成功与失败后旧文件保留
- 保存快照后实时现场变化不影响快照
- 标签组快照只保存选中的一个组，不混入其他标签组或未分组网页
- 旧版缺少 `scope` 的快照继续按完整现场读取，导入冲突时保留原范围
- 完整现场状态忽略标签组快照，分组状态可以精确返回实际命中的快照位置
- 删除快照只移除选中的本地文件，不改变其他快照或实时现场
- 同一标签组语境的标签组快照按时间收纳为版本序列，完整现场和名称或颜色变化后的标签组保持独立
- 版本序列只改变索引呈现，不合并不同版本的网页内容或改变搜索、导入导出和覆盖判断
- 搜索标题、域名、网址、组名和快照名
- 标签组生成独立结果，排在通过组名命中的成员网页之前，并保留准确的来源、快照、窗口、组标识与网页数量
- 搜索不合并重复网址
- 导出与导入往返一致
- 损坏文件、未知 schema、嵌套上下文不一致和标识冲突
- 导入任一快照无效时资料库保持原状
- 快照写入后磁盘内容核对
- 快照覆盖保留完整网址、重复数量与标签组语境
- 关闭部分网页后原快照继续覆盖剩余网页
- 不同来源快照不能参与覆盖，候选必须优先选择未覆盖项最少者
- 分组覆盖保留同一来源、组名、颜色、重复网址数量，不能合并两个同名分组
- 标签组折叠状态原子写入本机偏好，重新启动后仍可读取
- 内置扩展缺失时拒绝准备，完整时事务复制并逐文件核对
- Host 清单缺失、有效、损坏、扩展标识非法与应用路径变化
- Host 清单精确移除，不删除应用数据
- 命令创建、领取、结果和超时
- 结构化恢复结果保留动作、已创建数量、是否成组和失败阶段，旧版结果继续可解码
- 恢复回执准确区分完整成功、部分完成、失败和超时，并拒绝来源或动作错配的结果
- 部分完成与超时说明不包含自动重试，已创建标签不会触发清理命令
- 4MB Native Messaging 上限与长度前缀解析
- 来源在 30 秒边界内可用，超过边界后统一判定为过期
- Safari 合集固定保存浏览器来源、一个窗口、零个标签组、原顺序、重复网址与当前页
- Safari 合集名称为空、没有 Web 页面或伪装成 Chrome 合集时拒绝保存
- 旧版快照缺少浏览器来源字段时继续按 Chrome 读取
- Chrome 与 Safari 不能互相参与覆盖判断；Safari 合集不进入 Chrome 标签组版本序列
- 搜索结果保留浏览器来源，能够同时区分 Chrome“现在/快照”与 Safari“合集”
- “全部 / Chrome / Safari”搜索筛选在结果集合层隔离来源，专属范围零混入
- Chrome 快照与 Safari 合集单独导出的 JSON 数量和 `sourceKind` 完全匹配目标浏览器
- 导入预览准确汇总两种浏览器、标识冲突、网页和标签组，且预览本身零写入
- 只选择 Chrome 或 Safari 时仅写入对应来源；空选择、取消、空文件和无效文件零写入

### 2.2 Chrome 扩展

必须通过：

```bash
npm run check:extension
npm run test:extension
npm run test:bridge
./scripts/validate-extension.sh
npm run check:safari
```

测试覆盖：

- 普通窗口捕获
- 无痕窗口过滤
- 非 `http/https` 页面过滤
- 标签组名称、颜色、折叠状态和顺序
- 未分组标签
- 相同网址保留多次
- 400ms 防抖只发送最后一次完整现场
- `focusTab` 只聚焦窗口与标签
- `openUrl` 每次只创建一个标签
- `restoreGroup` 只组合本次命令新建的标签，并保留网址顺序、组名与颜色
- 创建标签中断时返回已经确认创建的数量和 `creatingTabs` 阶段
- 分组失败与组资料更新失败分别返回 `groupingTabs`、`updatingGroup`，并准确报告是否已经成组
- 标签组资料晚于标签列表时暂按未分组保存，输出结构仍通过校验
- 未知命令被拒绝

### 2.3 GitHub Actions

`.github/workflows/quality.yml` 在推送到 `main`、Pull Request 和用户手动触发时运行。必须满足：

- 只使用标准 `macos-15` runner，不使用收费的 larger runner。
- 顶层权限只有 `contents: read`，不写仓库、Issue、Pull Request、Package 或 Release。
- 执行 Swift 构建、测试与核心检查，Chrome 扩展行为和危险 API 扫描，Safari 按需读取扫描，以及 Release Bridge 往返。
- 不上传安装包或其他构建产物，不读取 Secret，不安装扩展、不注册 Host，也不连接真实 Chrome 或 Safari。
- 同一分支的新运行取消旧运行，避免重复占用 runner。

## 3. 静态安全验证

在扩展目录执行禁止 API 扫描，以下内容必须零命中：

```text
tabs.remove
tabs.move
tabs.discard
tabs.ungroup
windows.remove
```

`tabs.group` 与 `tabGroups.update` 只能在 `restoreGroup` 中各出现一次；静态检查必须确认 `tabs.group` 接收的是该命令收集的 `createdTabIds`。Node 行为测试进一步确认这些标识全部来自本次 `tabs.create` 返回值。

网络扫描必须确认不存在：

```text
fetch(
XMLHttpRequest
WebSocket
EventSource
```

允许 `http://` 与 `https://` 作为页面协议白名单和测试夹具；它们本身不代表扩展发起网络请求。

`manifest.json` 权限必须精确等于设计中的四项，不得出现通配 host 权限。

Safari 捕获源码必须确认：

- 只由用户点击调用，不存在计时器、目录监听或后台启动路径。
- AppleScript 只读取最前方窗口的标签标题、网址、顺序和当前页。
- 不包含关闭、移动、执行网页内 JavaScript、读取正文或修改标签的语句。
- 演示模式注入模拟捕获器，视觉验收不会触发真实 Safari 或权限提示。

## 4. 模拟数据

固定夹具至少包含：

- 2 个浏览器来源
- 3 个窗口
- 9 个标签组，其中 3 个未命名、3 个已折叠
- 33 个网页项
- 6 个未分组网页项
- 同一来源内 3 个完全相同的网址，位于两个未分组区域
- 固定、活动、播放声音和已丢弃状态各至少一个
- 5 个本地记录，其中 4 个 Chrome 快照、1 个 Safari 合集；两个 Chrome 快照是同一标签组的不同版本，一个 Chrome 来源离线
- Safari 模拟当前窗口含 4 个可保存网页、1 个非 Web 页面、1 个重复网址和明确当前页

另外生成 500 个网页项的性能夹具。

使用 `PAGECASE_PERFORMANCE=1` 启动隔离测试进程时，应用只载入 500 个网页项的性能夹具。

## 5. 视觉验收

使用模拟数据启动 Release 应用，不连接 Chrome。至少检查：

- 浅色与深色模式
- `1080 × 700` 默认窗口
- `860 × 560` 最小窗口
- Chrome 现在、Chrome 快照、Safari 按需收纳、Safari 合集、设置和搜索状态
- 侧栏必须把 Chrome 与 Safari 分成两个可一眼识别的区块；进入任一资料库后不得混入另一浏览器记录
- Safari 初始说明、模拟读取预览、保存命名、保存后合集详情和删除确认
- 全局搜索混排 Chrome 与 Safari 时，每行都有浏览器图标、名称和“现在/快照/合集”文字
- 搜索来源切换使用平直下划线样式；顶栏范围徽章与实际结果一致，清空搜索后恢复全部范围
- 设置页分别显示 Chrome 快照和 Safari 合集数量与单独导出动作，不把两类资料合成一行
- 混合备份导入预览、单独取消 Chrome 或 Safari、空选择禁用、取消零写入和冲突提示
- 菜单栏概况、唯一主窗口、关闭后驻留与搜索聚焦
- 设置页三步连接准备、无效扩展标识和 Host 状态
- 长标题、长网址、中文与英文混排
- 未命名标签组、空资料库、离线和数据过期
- 过期实时项显示“数据已过期”并禁用，离线快照项显示“Chrome 未连接”并禁用
- 搜索 Return 不得绕过过期或离线状态，设置页应分别统计已连接与过期来源
- 标签组搜索的“查看”应切换到准确来源或快照、展开并定位目标组；Return 不得触发恢复
- 快照标签组搜索结果的“恢复整组”应独立显示，离线时禁用，在线演示状态下仍须打开 Chrome 专属预览
- Chrome 恢复预览必须显示目标来源、组内网页、当前已打开、将新建和内存提示；重复网址按数量匹配但不得改变完整恢复列表
- Chrome 恢复成功回执必须在浅色模式显示已创建／应创建和已成组；部分完成回执必须在深色模式显示已保留标签、未成组和“不自动清理或重试”
- Chrome 回执在 Safari 页面和 Safari 专属搜索中不可见，返回 Chrome 后仍可继续查看，证明浏览器语义被隐藏而不是互相转换
- Safari 合集的“打开全部”继续使用 Safari 独立确认，不得显示 Chrome 恢复预览、已有网址计数或分组语义
- 新增未保存网页后显示未覆盖数量，保存并完成磁盘核对后立即切换为完整覆盖
- 未保存、部分保存和完整保存的标签组分别显示“保存该组”“保存最新版本”和“查看快照”
- Chrome 实时页显示准确的“已收纳 / 标签组总数”以及“全部 / 需保存 / 已收纳”数量；筛选后不出现不符合状态的标签组
- “需保存”与“已收纳”空状态给出对应下一步，未分组网页只在“全部”显示，窗口数量与网页数量按可见内容更新
- 模拟保存一个标签组后，“需保存”数量减少、“已收纳”数量增加，筛选结果立即更新；从搜索定位隐藏组时先恢复“全部”
- 收纳筛选只存在于 Chrome“现在”，Safari 按需收纳与合集页面不得出现该状态或参与覆盖判断
- 标签组保存对话框预填组名、日期和网页数；保存后旧版本仍在，新版本从磁盘核对
- “查看快照”打开实际覆盖该组的快照，并把对应组标题滚动到可见区域
- 快照索引与详情明确区分“完整现场”和“标签组”
- 标签组版本序列默认折叠，展开后显示较早版本；从搜索定位旧版本时自动展开
- 删除最新或较早版本后选中同一序列的剩余版本，其他快照和 Chrome 保持不变
- 快照详情直接显示删除入口，确认框包含快照名称与网页数量，取消后资料保持不变
- 键盘焦点、`⌘K`、上下键、Return 与 Escape
- 500 项搜索结果跨 50 项渲染批次的选择与自动滚动
- 减少动态效果和减少透明度

视觉验收可使用 `PAGECASE_APPEARANCE=light|dark` 强制单个测试进程的配色，不修改系统外观设置。

截图必须确认：

- 没有渐变、重阴影和大面积高饱和色
- 结构主要由排版、空白和 1px 分隔构成
- 彩色装订脊线清晰但不喧宾夺主
- 页面不是卡片墙
- 主要操作在首次看到时可以理解

## 6. 内存与 CPU

Release 应用加载 500 个网页项并空闲 60 秒后测量：

- 应用物理内存足迹目标不高于 80MB，验收上限 100MB
- 同时记录 RSS 作为诊断值；macOS 会把共享框架和图形映射计入每个进程的 RSS，因此不能只用 RSS 判断实际内存压力
- 当前版本与同机上一版本的 RSS 对照不得无解释增加 10MB 以上
- Bridge RSS 目标不高于 25MB
- 应用空闲 CPU 平均不高于 1%
- 文件轮询与目录监听不得持续唤醒造成可见 CPU 抖动
- 关闭主窗口后菜单栏驻留状态的物理内存足迹仍不得超过 100MB

如果物理内存足迹超过目标但未超过上限，交付时记录实测值和后续优化方向；超过验收上限，或 RSS 相对同机基线出现无法解释的显著增长，则当前版本不能交付。

## 7. 打包验证

必须确认：

- `scripts/build-app.sh` 在仅安装 Command Line Tools 的环境成功
- `.app` 具备正确名称、标识、最低系统版本与图标
- Bridge 位于应用包内固定路径
- ad-hoc 签名验证通过
- 应用可从 Finder 或 `open` 启动
- 安装脚本在模拟目录生成合法 Native Messaging manifest
- 卸载脚本只删除精确的 Host manifest，不删除应用数据
- `.app` 内包含扩展的全部五个运行与说明文件
- 应用内连接配置在 `PAGECASE_NATIVE_HOST_ROOT` 指向的隔离目录完成

真实 Chrome 扩展加载、Host 注册与标签定位，以及真实 Safari 权限、读取和打开动作不在本轮执行范围内，必须标记为“待用户授权的真实集成验证”。

## 8. 交付门槛

只有同时满足以下条件才可提交当前版本：

1. Swift 与 Node 测试全部通过。
2. Release 应用构建和启动成功。
3. 禁止 API 与网络扫描零命中。
4. 视觉验收无阻断问题。
5. 内存和 CPU 未超过验收上限。
6. 当前 Chrome 与 Safari 未被读取或操作。
7. 所有未做的真实环境验证被明确列出。
