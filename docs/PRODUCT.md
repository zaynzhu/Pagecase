# 页匣 · Pagecase 0.6 产品设计

## 1. 产品定义

页匣是一款面向低内存 Mac 的本地网页资料库。Chrome 通过极简扩展实时镜像已有窗口和标签组；Safari 通过用户点击后的一次性读取，把当前窗口保存成独立合集。两种浏览器共享搜索入口，但来源、资料库与恢复动作保持明确分离。

它不直接替用户管理内存。Chrome 的内存节省程序负责停用页面，用户本人负责确认快照完整后关闭不常用标签组。页匣负责消除“关闭后找不回来”的心理成本。

## 2. 目标用户与核心问题

目标用户长期打开大量 Chrome 页面，已经使用原生标签组形成稳定组织方式，但 8GB 内存设备无法持续承载全部活页面。

核心问题不是标签混乱，而是以下矛盾：

- 关闭页面能释放内存，但可能丢失分组语境和查找入口。
- 继续保留页面最安心，但 Chrome 与交换空间长期承压。
- 普通书签缺少窗口、标签组、顺序和重复页面的上下文。
- 现有工具常要求改变工作方式，或加入不需要的账号、AI、协作和付费功能。

## 3. 当前成功定义

当前版本必须完成一个安全闭环：

1. 使用扩展只读捕获普通 Chrome 窗口、原生标签组和网页项。
2. 在原生 macOS 应用中按原顺序展示实时现场。
3. 用户主动保存完整现场或一个标签组，实时变化不会改写已保存内容。
4. 用户可以跨实时现场与资料库搜索标题、域名、网址、标签组和快照名称，并把标签组作为独立结果查看。
5. 点击实时网页项只定位已有标签。
6. 点击快照网页项只新建一个标签；点击“恢复整组”并确认后，按原顺序新建并组合该组网页。
7. 用户可以导出和重新导入完整资料库。
8. 整个过程不存在关闭、移动、挂起或重组已有标签的代码路径；整组恢复只组合当前命令新建的标签。
9. 关闭主窗口后，用户仍可从菜单栏查看概况并快速返回搜索。
10. 用户可以只在需要时读取 Safari 最前方窗口，核对预览并命名保存；应用不持续监测 Safari，也不会把 Safari 合集混进 Chrome 快照。

## 4. 当前范围

### 4.1 实时现场

- 支持一个或多个安装了扩展的 Chrome 用户配置。
- 每个来源使用独立随机标识；不尝试读取 Chrome 账号或配置名称。
- 展示普通窗口、标签组、未分组标签、标题、网址、顺序、固定、活动、播放声音和已被 Chrome 丢弃状态。
- 每个标签组独立显示保存覆盖状态；标签组与未分组区域均可折叠，折叠状态持久保存在本机。
- 保留重复网址，不自动去重。
- 忽略无痕窗口。
- 只保存 `http://` 与 `https://` 页面，不保存 `file://`、`chrome://`、扩展页或其他内部协议。

### 4.2 Chrome 快照资料库

- 从某个来源的完整实时现场创建命名快照。
- 从实时标签组标题直接创建只包含该组的命名快照。
- 快照保存窗口、标签组、网页项、来源标识和创建时间。
- 快照明确标记为“完整现场”或“标签组”；旧版未标记的快照按完整现场读取。
- 快照不可被实时同步改写。
- 实时页只用完整现场快照判断整个现场是否已经保存，避免单组快照造成整体安全误判。
- 覆盖核对保留完整网址、重复数量、标签组名称与颜色；不同来源不能互相覆盖。
- 用户手动关闭部分网页后，只要剩余网页仍包含在原快照中，就继续显示已覆盖。
- 分组覆盖按同一来源、组名、颜色、完整网址和重复数量核对；同名分组不能互相拼接成完整覆盖。
- 分组覆盖同时接受完整现场快照与标签组快照；完整匹配时可直接跳到实际保存该组的位置。
- 未保存标签组提供“保存该组”，新增网页后提供“保存最新版本”；旧版本不会被覆盖或自动删除。
- 同一标签组语境的多份标签组快照在资料库中收纳为一个“标签组版本序列”，默认显示最新版，较早版本按需展开。
- 版本序列只改变资料库索引的呈现：每份快照继续独立存储、搜索、导出、重命名和删除，覆盖判断也不跨版本合并内容。
- 完整现场快照始终独立显示；来源、窗口/标签组身份、组名或颜色不同的标签组快照不会进入同一序列。
- 保存成功前从磁盘重新读取并核对完整内容。
- 支持重命名与带确认的删除。
- 支持导出全部资料库为一个带版本号的 JSON 文件。
- 支持只导出 Chrome 快照或只导出 Safari 合集；浏览器专属导出不得包含另一浏览器记录。
- 支持导入由页匣导出的 JSON；导入前完整校验，发生标识冲突时保留两份并生成新标识。
- 选择导入文件后先显示只读预览，按 Chrome 快照与 Safari 合集分别汇总资料、网页、标签组和标识冲突数量。
- 混合资料库允许只选择 Chrome 或 Safari；未选择任何来源时不能确认，取消或关闭预览不得产生写入。
- 导入使用暂存目录与目录级替换，任一快照无效时不写入部分资料。

### 4.3 Safari 按需收纳与合集

- 侧栏使用独立的 Safari 分区，包含“按需收纳”与“合集”，不复用 Chrome 的“现在”与“快照”命名。
- 用户先在 Safari 打开目标原生标签组并让它成为最前方窗口，再在页匣中点击“读取当前窗口”。
- 每次点击只启动一次 AppleScript，读取该窗口中 `http/https` 页面的标题、网址、顺序和当前页状态；完成后立即结束，不建立轮询、文件监听或常驻辅助进程。
- Safari 自动化接口不提供可靠的原生标签组名称，因此页匣不猜测名称。预览确认时由用户填写合集名称。
- 捕获结果先以只读预览展示；只有用户再次点击保存并通过校验后，才原子写入资料库。
- Safari 合集固定标记 `sourceKind = safari`、`scope = collection`，必须恰好包含一个窗口、零个标签组和至少一个网页。
- 重复网址与原顺序完整保留；非 Web 协议会跳过并显示数量，不读取网页正文、截图、历史记录或登录状态。
- 用户可点击单页在 Safari 打开，也可在确认网页数量后“在 Safari 打开全部”；这些动作只创建新页面，不更改原标签组。
- 用户仍需自行关闭或删除 Safari 中的原标签组，页匣永远不代替用户释放内存。
- Safari 合集与 Chrome 快照分别浏览、统计和删除；同一个网址也不会跨浏览器合并。

### 4.4 搜索与打开

- `⌘K` 聚焦全局搜索。
- 搜索匹配快照名称、标签组名称、网页标题、域名和完整网址。
- 搜索结果保留浏览器、来源、窗口、标签组、快照或合集语境；每行必须显示 Chrome 或 Safari 图标与文字，不能只靠颜色区分。
- 搜索结果顶部提供“全部 / Chrome / Safari”来源筛选。浏览器专属范围必须从结果集合中完全排除另一浏览器，而不是只做视觉隐藏。
- 搜索期间顶栏状态必须反映搜索范围：“全部浏览器”“仅看 Chrome”或“仅看 Safari”，不能沿用进入搜索前的页面来源。
- 上下键移动当前结果，Return 执行选中项，Escape 清空搜索。
- 标签组名称匹配生成独立的“标签组”结果，并排在通过组名命中的成员网页之前；不把未分组区域伪装成标签组。
- 标签组结果的主动作统一为“查看”：切换到对应实时来源或快照、展开目标组并滚动到组标题，不向 Chrome 发送命令。
- 快照标签组结果另有独立的“恢复整组”动作；必须确认网页数量后才发送 `restoreGroup`。Return 只执行“查看”，不会直接恢复。
- 点击实时结果向对应扩展发送 `focusTab`，只激活目标窗口和标签。
- 点击快照结果向原来源扩展发送 `openUrl`，只创建一个新标签。
- 快照分组提供“恢复整组”；确认对话框显示将打开的网页数，再发送 `restoreGroup`。
- `restoreGroup` 按原顺序创建后台标签，只把本次命令返回的标签标识交给 Chrome 分组 API，并恢复原组名和颜色。
- 来源离线时，快照结果显示“Chrome 未连接”，不静默改用其他浏览器。
- 来源不可用时，网页结果不能创建命令，快照标签组的恢复动作禁用；标签组“查看”和本地浏览始终可用。
- Safari 合集网页使用“在 Safari 打开”，合集结果只进入 Safari 合集详情；不能出现 Chrome 的“定位”或“恢复整组”。

### 4.5 状态与反馈

- 清楚区分“已连接”“等待 Chrome”“数据过期”和“命令失败”。
- 应用内展示三步连接准备，检查扩展文件与 Native Messaging Host 状态。
- 用户明确点击后才准备扩展文件或写入、移除 Host 清单。
- 实时数据超过 30 秒未更新时标为“数据过期”，仍可查看但不可定位。
- 实时列表、快照、搜索、侧栏和设置必须使用同一来源状态，不允许同一来源在不同页面显示矛盾。
- 新增网页或改变标签组语境后，实时页显示尚未包含在最佳快照中的网页数量。
- 快照保存、重命名、删除、导入和导出均提供明确结果。
- 设置页分别显示 Chrome 快照与 Safari 合集数量和单独导出动作，完整导入与完整备份作为次级入口保留。
- 导入确认使用独立原生面板；Chrome 与 Safari 行必须同时使用名称、图标、识别色和数量，不只靠颜色区分。
- 空状态解释下一步，不使用营销文案。

### 4.6 菜单栏入口

- 使用原生菜单栏图标，不创建自绘常驻弹窗。
- 菜单分别显示 Chrome 实时网页数、Chrome 快照数和 Safari 合集数。
- “打开页匣”只恢复唯一主窗口，不重复创建多个窗口。
- “搜索网页…”恢复主窗口并把键盘焦点交给全局搜索。
- 关闭主窗口不退出应用；菜单提供明确的退出入口。

## 5. 明确不做

当前版本不包含以下能力：

- 自动关闭、定时关闭、批量关闭或自动挂起标签。
- 移动已有标签、修改已有标签组或恢复整个窗口。
- 网页正文、截图、阅读进度、滚动位置、表单状态或登录状态保存。
- 浏览历史、下载记录、书签和无痕窗口读取。
- 云同步、账号系统、团队协作、AI 分类和网页推荐。
- 开机自启、自动更新和正式签名发布。
- Safari 后台监测、Safari 扩展、Safari 原生标签组名称同步或 Safari 组内增量更新。
- Firefox、Edge 等其他浏览器支持。
- 内存清理或对 Chrome Memory Saver 的控制。

这些不是未完成项，而是当前版本刻意排除的边界。

## 6. 关键用户流程

### 6.1 首次连接

1. 用户在设置页点击“显示扩展文件”，页匣将内置连接器完整复制到本地数据目录并在 Finder 中选中。
2. 用户自行在 `chrome://extensions` 加载这个文件夹；页匣不打开或操作 Chrome。
3. 用户将 Chrome 显示的扩展标识粘贴回设置页。
4. 用户点击“配置本地连接”，页匣写入只允许该扩展访问的 Host 清单。
5. 扩展连接本地主机并发送只读实时现场。
6. 应用显示来源、窗口数、标签组数、网页数和最后更新时间。
7. 如果连接失败，设置页区分清单缺失、格式损坏和应用位置变化，不改动 Chrome 标签。

自动化开发和验收不执行该流程，只验证隔离安装输出和模拟协议。用户已手动完成首次连接并确认实时现场正常显示。

### 6.2 保存快照

1. 用户在“现在”页面选择来源。
2. 点击“保存当前现场”。
3. 对话框预填日期与网页数量，用户输入名称。
4. 应用复制当前数据并原子写入本地资料库。
5. 保存成功后显示网页数和标签组数，Chrome 保持不变。
6. 实时页立即显示“当前所有网页已包含”及对应快照名称。

### 6.3 保存一个标签组

1. 用户在“现在”页面看到某组为“未保存”或有新增网页。
2. 点击“保存该组”或“保存最新版本”。
3. 对话框预填组名、日期和网页数量，用户可以修改名称。
4. 应用在确认时重新查找当前标签组，只复制该组并原子写入本地资料库。
5. 保存成功后从磁盘重新读取核对，该组立即显示“已保存”，Chrome 保持不变。
6. 已保存组的操作变为“查看快照”，点击后打开实际覆盖该组的快照并定位到组标题。

如果标签组在保存对话框打开期间已经离开当前现场，保存失败并提示用户，不会写入过期的部分资料。

### 6.4 找到一个页面或标签组

1. 用户在主窗口按 `⌘K`，或从菜单栏选择“搜索网页…”。
2. 输入标题、域名或标签组关键词。
3. 结果同时显示网页项与独立标签组项，并标注实时、快照、来源和位置语境。
4. 点击实时网页项定位已有标签；点击快照网页项只打开一个新标签。
5. 点击标签组的“查看”在页匣中打开并展开目标位置；快照标签组只有点击独立“恢复整组”并确认后才创建标签。

### 6.5 用户自行释放内存

1. 用户在页匣中看到完整现场已保存，或准备关闭的目标标签组显示“已保存”。
2. 用户回到 Chrome，自行关闭不常用标签组。
3. 页匣的实时现场随之更新，快照保持不变。
4. 以后搜索并打开需要的单页，或从快照中恢复一个完整标签组。

页匣不提供或暗示自动关闭按钮。

### 6.6 恢复完整标签组

1. 用户在快照中找到目标标签组并点击“恢复整组”。
2. 页匣显示组名和将新建的网页数量，用户明确确认。
3. 来源仍在线时，扩展按快照顺序创建后台标签。
4. 扩展只组合这次命令新建的标签，并设置原组名和颜色。
5. 任一已有标签都不会被移动、关闭、解除分组或加入新组。

### 6.7 删除快照

1. 用户在快照资料库中选中目标快照。
2. 点击标题旁直接可见的“删除快照”。
3. 确认框显示快照名称和网页数量，并明确操作无法撤销、不会影响 Chrome。
4. 用户确认后只删除对应的本地快照文件；其他快照与实时现场保持不变。
5. 如果删除的是版本序列中的当前版本，资料库继续选中同一序列的剩余版本，不把用户带到无关快照。

### 6.8 浏览标签组版本

1. 用户多次保存同一个标签组，每次保存仍生成独立快照文件。
2. 快照索引将这些快照显示为一个默认折叠的标签组版本序列，并标明版本数量。
3. 点击序列主体打开最新版；点击箭头展开较早版本。
4. 选择较早版本后，右侧完整显示该版本当时的网页数量和内容。
5. 从搜索结果定位到较早版本时，索引自动展开对应序列，使当前版本保持可见。

版本序列不是自动去重或内容合并。搜索和导出仍保留每一份独立快照。

### 6.9 收纳 Safari 当前窗口

1. 用户在 Safari 切换到准备收纳的原生标签组，使目标窗口位于最前方。
2. 用户进入页匣的 Safari“按需收纳”，点击“读取当前窗口”。
3. 系统在需要时请求一次自动化权限；页匣读取标题、网址、顺序和当前页后立即停止。
4. 页匣展示完整预览、重复网址和被跳过的非 Web 页面数量，不在预览阶段写入资料库。
5. 用户点击“保存为合集”，填写一个页匣内名称；保存后重新从磁盘读取并核对浏览器来源与内容。
6. 用户确认合集可搜索、可打开后，自行回到 Safari 关闭或删除原标签组。

开发与自动化验收只使用模拟捕获器。真实 Safari 权限提示、真实标签读取和打开动作必须得到用户单独授权后再验证。

## 7. 失败与边界场景

- 扩展断开：保留最后一次实时现场并标记过期，不删除数据。
- Chrome 关闭：来源显示离线，快照仍可浏览和导出。
- 页面在点击前已关闭：`focusTab` 返回“页面已经关闭”，实时现场随后刷新。
- 相同网址存在多次：每条结果保留各自窗口和标签组，不合并。
- 网页标题为空：显示域名；网址也无效时不接收该项。
- 标签组无名称：界面显示“未命名标签组”，但不修改 Chrome。
- 导入文件损坏或版本不支持：整次导入失败，不写入部分数据。
- 本地磁盘写入失败：保留原文件并显示路径与原因。
- Native Messaging 消息超过 4MB：拒绝写入并记录结构化错误。
- 整组恢复期间 Chrome API 失败：报告失败；已经创建的标签保持可见，不用关闭操作做自动回滚。
- 标签列表与标签组资料短暂不同步：该次捕获暂按未分组保存，下一次防抖捕获自动纠正。
- Safari 未运行或没有窗口：显示可执行的提示，不创建空合集。
- Safari 自动化权限被拒绝：解释如何在系统设置中授权，不循环请求，也不降级到辅助功能抓取。
- Safari 当前窗口包含内部页或空网址：跳过非 `http/https` 项并显示数量；若没有可保存网页则停止。
- Safari 原生标签组名称不可读取：由用户命名页匣合集，不用窗口标题或首个网页标题猜测。

## 8. 隐私与安全

- 数据只写入当前用户的 `Application Support/Pagecase`。
- 文件默认使用当前用户可读写权限。
- 不包含遥测、分析、崩溃上报和网络请求。
- 完整网址可能包含敏感查询参数，导出前明确提示文件包含浏览信息。
- 扩展源码保持可审计，禁止关闭、移动、挂起和解除分组 API。
- 标签组写 API 只能存在于 `restoreGroup`，并且只能接收该命令刚创建的标签标识。
- 所有会改变 Chrome 可见状态的行为都来自用户单次点击；整组恢复还必须经过网页数量确认。
- Safari 捕获只在用户点击后运行一次 AppleScript，不执行网页脚本、不读取正文、不轮询、不启动常驻进程，也不关闭或重排页面。
- 每份快照持久保存浏览器种类和来源标签；Chrome 与 Safari 不互相参与覆盖判断、版本序列或浏览器专属动作。
