# 页匣 · Pagecase 0.2 产品设计

## 1. 产品定义

页匣是一款面向低内存 Mac 的本地网页资料库。它实时镜像 Chrome 已有的窗口和标签组，让用户在不破坏现有整理方式的前提下保存不可变快照、快速搜索页面，并按需定位、打开单页或恢复一个完整标签组。

它不直接替用户管理内存。Chrome 的内存节省程序负责停用页面，用户本人负责确认快照完整后关闭不常用标签组。页匣负责消除“关闭后找不回来”的心理成本。

## 2. 目标用户与核心问题

目标用户长期打开大量 Chrome 页面，已经使用原生标签组形成稳定组织方式，但 8GB 内存设备无法持续承载全部活页面。

核心问题不是标签混乱，而是以下矛盾：

- 关闭页面能释放内存，但可能丢失分组语境和查找入口。
- 继续保留页面最安心，但 Chrome 与交换空间长期承压。
- 普通书签缺少窗口、标签组、顺序和重复页面的上下文。
- 现有工具常要求改变工作方式，或加入不需要的账号、AI、协作和付费功能。

## 3. 当前成功定义

当前版本必须完成一个安全闭环：

1. 使用扩展只读捕获普通 Chrome 窗口、原生标签组和网页项。
2. 在原生 macOS 应用中按原顺序展示实时现场。
3. 用户主动保存命名快照，实时变化不会改写已保存内容。
4. 用户可以跨实时现场与资料库搜索标题、域名、网址、标签组和快照名称。
5. 点击实时网页项只定位已有标签。
6. 点击快照网页项只新建一个标签；点击“恢复整组”并确认后，按原顺序新建并组合该组网页。
7. 用户可以导出和重新导入完整资料库。
8. 整个过程不存在关闭、移动、挂起或重组已有标签的代码路径；整组恢复只组合当前命令新建的标签。
9. 关闭主窗口后，用户仍可从菜单栏查看概况并快速返回搜索。

## 4. 当前范围

### 4.1 实时现场

- 支持一个或多个安装了扩展的 Chrome 用户配置。
- 每个来源使用独立随机标识；不尝试读取 Chrome 账号或配置名称。
- 展示普通窗口、标签组、未分组标签、标题、网址、顺序、固定、活动、播放声音和已被 Chrome 丢弃状态。
- 每个标签组独立显示保存覆盖状态；标签组与未分组区域均可折叠，折叠状态持久保存在本机。
- 保留重复网址，不自动去重。
- 忽略无痕窗口。
- 只保存 `http://` 与 `https://` 页面，不保存 `file://`、`chrome://`、扩展页或其他内部协议。

### 4.2 快照资料库

- 从某个来源的完整实时现场创建命名快照。
- 快照保存窗口、标签组、网页项、来源标识和创建时间。
- 快照不可被实时同步改写。
- 实时页持续提示当前网页是否都已包含在某个同来源快照中。
- 覆盖核对保留完整网址、重复数量、标签组名称与颜色；不同来源不能互相覆盖。
- 用户手动关闭部分网页后，只要剩余网页仍包含在原快照中，就继续显示已覆盖。
- 分组覆盖按同一来源、组名、颜色、完整网址和重复数量核对；同名分组不能互相拼接成完整覆盖。
- 保存成功前从磁盘重新读取并核对完整内容。
- 支持重命名与带确认的删除。
- 支持导出全部资料库为一个带版本号的 JSON 文件。
- 支持导入由页匣导出的 JSON；导入前完整校验，发生标识冲突时保留两份并生成新标识。
- 导入使用暂存目录与目录级替换，任一快照无效时不写入部分资料。

### 4.3 搜索与打开

- `⌘K` 聚焦全局搜索。
- 搜索匹配快照名称、标签组名称、网页标题、域名和完整网址。
- 搜索结果保留来源、窗口、标签组与快照语境。
- 上下键移动当前结果，Return 执行选中项，Escape 清空搜索。
- 点击实时结果向对应扩展发送 `focusTab`，只激活目标窗口和标签。
- 点击快照结果向原来源扩展发送 `openUrl`，只创建一个新标签。
- 快照分组提供“恢复整组”；确认对话框显示将打开的网页数，再发送 `restoreGroup`。
- `restoreGroup` 按原顺序创建后台标签，只把本次命令返回的标签标识交给 Chrome 分组 API，并恢复原组名和颜色。
- 来源离线时，快照结果显示“Chrome 未连接”，不静默改用其他浏览器。
- 来源不可用时，列表点击与 Return 都不能创建命令，只保留搜索和浏览能力。

### 4.4 状态与反馈

- 清楚区分“已连接”“等待 Chrome”“数据过期”和“命令失败”。
- 应用内展示三步连接准备，检查扩展文件与 Native Messaging Host 状态。
- 用户明确点击后才准备扩展文件或写入、移除 Host 清单。
- 实时数据超过 30 秒未更新时标为“数据过期”，仍可查看但不可定位。
- 实时列表、快照、搜索、侧栏和设置必须使用同一来源状态，不允许同一来源在不同页面显示矛盾。
- 新增网页或改变标签组语境后，实时页显示尚未包含在最佳快照中的网页数量。
- 快照保存、重命名、删除、导入和导出均提供明确结果。
- 空状态解释下一步，不使用营销文案。

### 4.5 菜单栏入口

- 使用原生菜单栏图标，不创建自绘常驻弹窗。
- 菜单显示来源状态、实时网页数和快照数。
- “打开页匣”只恢复唯一主窗口，不重复创建多个窗口。
- “搜索网页…”恢复主窗口并把键盘焦点交给全局搜索。
- 关闭主窗口不退出应用；菜单提供明确的退出入口。

## 5. 明确不做

当前版本不包含以下能力：

- 自动关闭、定时关闭、批量关闭或自动挂起标签。
- 移动已有标签、修改已有标签组或恢复整个窗口。
- 网页正文、截图、阅读进度、滚动位置、表单状态或登录状态保存。
- 浏览历史、下载记录、书签和无痕窗口读取。
- 云同步、账号系统、团队协作、AI 分类和网页推荐。
- 开机自启、自动更新和正式签名发布。
- Chrome 以外的浏览器支持。
- 内存清理或对 Chrome Memory Saver 的控制。

这些不是未完成项，而是当前版本刻意排除的边界。

## 6. 关键用户流程

### 6.1 首次连接

1. 用户在设置页点击“显示扩展文件”，页匣将内置连接器完整复制到本地数据目录并在 Finder 中选中。
2. 用户自行在 `chrome://extensions` 加载这个文件夹；页匣不打开或操作 Chrome。
3. 用户将 Chrome 显示的扩展标识粘贴回设置页。
4. 用户点击“配置本地连接”，页匣写入只允许该扩展访问的 Host 清单。
5. 扩展连接本地主机并发送只读实时现场。
6. 应用显示来源、窗口数、标签组数、网页数和最后更新时间。
7. 如果连接失败，设置页区分清单缺失、格式损坏和应用位置变化，不改动 Chrome 标签。

自动化开发和验收不执行该流程，只验证隔离安装输出和模拟协议。用户已手动完成首次连接并确认实时现场正常显示。

### 6.2 保存快照

1. 用户在“现在”页面选择来源。
2. 点击“保存当前现场”。
3. 对话框预填日期与网页数量，用户输入名称。
4. 应用复制当前数据并原子写入本地资料库。
5. 保存成功后显示网页数和标签组数，Chrome 保持不变。
6. 实时页立即显示“当前所有网页已包含”及对应快照名称。

### 6.3 找到一个页面

1. 用户在主窗口按 `⌘K`，或从菜单栏选择“搜索网页…”。
2. 输入标题、域名或标签组关键词。
3. 结果同时显示实时项与快照项，并标注上下文。
4. 点击实时项定位已有标签；点击快照项只打开一个新标签。

### 6.4 用户自行释放内存

1. 用户在页匣中看到“当前所有网页已包含在快照”的持久状态。
2. 用户回到 Chrome，自行关闭不常用标签组。
3. 页匣的实时现场随之更新，快照保持不变。
4. 以后搜索并打开需要的单页，或从快照中恢复一个完整标签组。

页匣不提供或暗示自动关闭按钮。

### 6.5 恢复完整标签组

1. 用户在快照中找到目标标签组并点击“恢复整组”。
2. 页匣显示组名和将新建的网页数量，用户明确确认。
3. 来源仍在线时，扩展按快照顺序创建后台标签。
4. 扩展只组合这次命令新建的标签，并设置原组名和颜色。
5. 任一已有标签都不会被移动、关闭、解除分组或加入新组。

## 7. 失败与边界场景

- 扩展断开：保留最后一次实时现场并标记过期，不删除数据。
- Chrome 关闭：来源显示离线，快照仍可浏览和导出。
- 页面在点击前已关闭：`focusTab` 返回“页面已经关闭”，实时现场随后刷新。
- 相同网址存在多次：每条结果保留各自窗口和标签组，不合并。
- 网页标题为空：显示域名；网址也无效时不接收该项。
- 标签组无名称：界面显示“未命名标签组”，但不修改 Chrome。
- 导入文件损坏或版本不支持：整次导入失败，不写入部分数据。
- 本地磁盘写入失败：保留原文件并显示路径与原因。
- Native Messaging 消息超过 4MB：拒绝写入并记录结构化错误。
- 整组恢复期间 Chrome API 失败：报告失败；已经创建的标签保持可见，不用关闭操作做自动回滚。
- 标签列表与标签组资料短暂不同步：该次捕获暂按未分组保存，下一次防抖捕获自动纠正。

## 8. 隐私与安全

- 数据只写入当前用户的 `Application Support/Pagecase`。
- 文件默认使用当前用户可读写权限。
- 不包含遥测、分析、崩溃上报和网络请求。
- 完整网址可能包含敏感查询参数，导出前明确提示文件包含浏览信息。
- 扩展源码保持可审计，禁止关闭、移动、挂起和解除分组 API。
- 标签组写 API 只能存在于 `restoreGroup`，并且只能接收该命令刚创建的标签标识。
- 所有会改变 Chrome 可见状态的行为都来自用户单次点击；整组恢复还必须经过网页数量确认。

## 9. 交付物

- 可通过 Swift Package 构建的 macOS 应用。
- 可手动加载的 Manifest V3 Chrome 扩展。
- Native Messaging Host 可执行文件。
- 随 `.app` 打包的完整 Chrome 连接器。
- 应用内显式连接准备、Host 配置与精确移除。
- 不自动运行的构建、打包、安装与卸载脚本，作为备用入口。
- 多窗口、多标签组和重复网址的模拟数据。
- Swift 与 Node 自动化测试。
- Release `.app` 构建产物和视觉验收截图。
- 明确记录的内存、CPU、安全与未做真实 Chrome 集成验证结论。
