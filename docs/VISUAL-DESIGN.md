# 页匣 · Pagecase 0.6 视觉与交互设计

## Design Read

Reading this as: 面向大量 Chrome 与 Safari 标签用户的 macOS 原生工具，采用安静、可信、资料柜式的实用极简语言，依托 SwiftUI 系统组件与克制的编辑排版。Chrome 是持续连接的蓝色工作现场，Safari 是明确按需的紫色收纳入口，两者不可在视觉上混成一个资料池。

当前设计仅使用 `minimalist-ui`。网页专属的 hero、Tailwind、滚动章节和营销组件不适用于本产品，已转换为原生窗口、键盘导航和列表微交互。

## 1. 设计推演

### 第一轮

最初方向是温暖单色背景、白色卡片和低饱和标签色，使用常见侧栏加卡片网格。

### 自我批评

这个方向容易成为另一个 Notion 风格模板：

- 大量独立卡片会增加视觉噪声，也浪费小屏幕空间。
- Bento 网格适合营销展示，不适合快速扫描数十个网页。
- Chrome 标签组颜色如果变成大面积背景，会破坏克制感。
- 过度圆角和阴影会让工具显得松软，降低信息密度。

### 修订方向

最终采用“索引资料柜”：

- 页面主体是连续的文档式列表，不是卡片墙。
- Chrome 标签组颜色只表现为 4px 的装订脊线和小型状态标记。
- 快照像抽屉索引，标题使用系统衬线体，数据与快捷键使用等宽体。
- 结构主要依赖空白、1px 分隔和排版层级，不依赖装饰。

这一条彩色装订脊线是产品的视觉签名：它把 Chrome 原生分组语义带入资料库，同时不复制 Chrome 的标签栏外观。

## 2. 视觉令牌

### 浅色模式

| 名称 | 色值 | 用途 |
|---|---:|---|
| Canvas | `#F7F6F3` | 窗口底色 |
| Surface | `#FFFFFF` | 主内容与弹窗 |
| Ink | `#2F3437` | 主文字 |
| Muted | `#787774` | 次级信息 |
| Border | `#EAEAEA` | 1px 分隔 |
| Live tint | `#E1F3FE` | 已连接、实时 |
| Live ink | `#1F6C9F` | 实时状态文字 |
| Safe tint | `#EDF3EC` | 已保存、安全 |
| Safe ink | `#346538` | 成功状态文字 |
| Stale tint | `#FBF3DB` | 数据过期、离线 |
| Stale ink | `#956400` | 警示状态文字 |
| Error tint | `#FDEBEC` | 错误 |
| Error ink | `#9F2F2D` | 错误文字 |

浏览器来源另有克制的识别色：Chrome 使用低饱和蓝，Safari 使用低饱和紫。颜色只用于 3px 侧栏脊线、图标和小型徽章；所有位置同时写出浏览器名称，不能依赖色觉区分。

### 深色模式

深色模式保留相同语义，但不简单反色：

- Canvas `#171716`
- Surface `#20201F`
- Ink `#F0EFEC`
- Muted `#A5A29B`
- Border `#30302E`
- 语义色使用相同色相、较低明度的背景与较高明度的文字

### 标签组颜色

Chrome 的九种标签组颜色映射为低饱和 SwiftUI 色。它们只用于装订脊线、组标题圆点和选中态的轻微底色，不用于整块背景。

## 3. 字体

- 页面标题与快照名称：New York 或系统 `.serif`，Semibold。
- 主要界面与网页标题：SF Pro Text / 系统 `.default`。
- 数量、时间、域名和快捷键：SF Mono / 系统 `.monospaced`。
- 主文字不使用纯黑。
- 网页标题最多两行；网址与域名保持单行并截断中部。

不捆绑外部字体，避免增加应用体积与加载开销。

## 4. 主窗口

建议默认尺寸为 `1080 × 700`，最小尺寸为 `860 × 560`。

```text
┌────────────────────────────────────────────────────────────────────┐
│ 页匣               [ 搜索网页、标签组或快照        ⌘K ]   已连接  │
├───────────────┬────────────────────────────────────────────────────┤
│               │  现在                           保存当前现场       │
│  CHROME        │  Chrome · 2 个窗口 · 最后更新 14:20               │
│  现在      84 │                                                    │
│  快照      12 │  ┃ 开发                                            │
│  来源         │  ┃  GitHub · Pull requests              github.com │
│  Chrome       │  ┃  本地项目文档                    localhost:3000 │
│               │  ┃  API 参考                         developer... │
│  SAFARI        │                                                    │
│  按需收纳      │                                                    │
│  合集       3 │                                                    │
│  设置         │                                                    │
│               │                                                    │
│               │  │ 未分组                                          │

│               │                                                    │
├───────────────┴────────────────────────────────────────────────────┤
│ 数据只保存在本机 · 不会自动修改 Chrome 或 Safari 标签              │
└────────────────────────────────────────────────────────────────────┘
```

### 侧栏

- 固定宽度 208px。
- 固定分成 `CHROME` 与 `SAFARI` 两个大区。Chrome 内是“现在”“快照”和实时来源；Safari 内是“按需收纳”“合集”。设置位于两个来源区之后。
- 分区使用独立浏览器图标、英文小标题、中文功能名、数量和左侧细脊线，不能只通过列表顺序区分。
- 选中项使用浅灰背景和 6px 圆角，不使用彩色胶囊。
- 数量使用等宽字体，不与标题争夺注意力。

### 顶栏

- 搜索是视觉中心，但不做悬浮大胶囊。
- 状态标记紧凑显示“已连接”“数据过期”或“等待 Chrome”。
- 状态不能只依赖颜色；过期和离线行使用文字说明并降低透明度，操作控件保持可读但不可触发。
- 只有当前页面相关的主操作出现在右侧。

### 菜单栏

- 使用可在 16px 清楚辨认的单色资料匣符号，不放文字常驻占宽。
- 使用系统原生菜单，不制作卡片式弹窗或迷你版主窗口。
- 菜单只包含来源概况、实时网页数、快照数、打开、搜索和退出。
- 菜单状态使用文字表达，不只依赖图标颜色。

### 内容区

- 使用连续列表和分隔线，不套多层卡片。
- 实时页元数据下方使用一行完整现场状态：绿色盾牌表示所有网页已包含在完整现场快照中，黄色盾牌说明尚未保存或仍有未覆盖网页。
- 完整现场状态显示具体数量与快照名称；没有完整现场快照时明确提示可按下方标签组状态逐组确认，不把单组快照误作整体安全证明。
- 完整现场状态下方显示“已收纳 / 标签组总数”和“全部 / 需保存 / 已收纳”平直筛选；使用 2px 下划线、低饱和黄绿语义色和明确数量，不使用胶囊或浮层。
- “已收纳”旁永久说明关闭仍由用户在 Chrome 手动完成；筛选为空时使用内联图标、标题和下一步，不增加空状态卡片。
- 窄窗口下统计说明与筛选允许纵向排列，不能压缩成难以点击的文字；当前筛选通过可访问性选中状态表达，不能只依赖下划线颜色。
- 每个标签组只有一个白色表面，圆角 10px，边框 1px。
- 组标题同时显示网页数量和“已收纳 / N 个未保存 / 未保存”；绿色与黄色状态均带图标和文字。
- 组标题右侧只显示一个与状态对应的动作：“保存该组”“保存最新版本”或“查看快照”。
- “查看快照”打开实际覆盖该组的版本，并把目标组滚动到可见区域。
- 点击组标题折叠或展开网页列表，箭头明确表示状态；折叠选择在应用重启后保持。
- 组内行高 48–56px，足以扫描又不会稀疏。
- 活动网页用轻微底色和左侧短标记表示，不改变整行字体颜色。

## 5. 搜索状态

按 `⌘K` 后仍在原窗口内搜索，不弹出覆盖全屏的命令面板。

```text
“AI 工具” 的 8 个结果

浏览器  类型  标题          语境                            主动作  次动作
Chrome  快照  AI 工具       工具研究 › 窗口 1                查看   恢复整组
Chrome  现在  OpenAI 文档   网页 › AI 工具                   定位
Safari  合集  周末长文       周末阅读合集                     打开
```

- 实时与快照结果不混淆，网页动作使用“定位”与“打开”，标签组主动作使用“查看”。
- Chrome 与 Safari 结果可以混排，但每行左侧必须同时显示浏览器图标、浏览器名称和“现在/快照/合集”类型。
- 标题下方使用平直的“全部 / Chrome / Safari”来源切换，不使用大胶囊或浮动筛选卡；选中项只增加 2px 下划线与对应低饱和来源色。
- 搜索期间顶栏徽章改为“全部浏览器”“仅看 Chrome”或“仅看 Safari”，不保留进入搜索前页面的来源徽章。
- 标签组行明确标记类型与网页数量；“查看”占主交互区域，快照标签组的“恢复整组”以分隔后的次要按钮呈现。
- Safari 网页主动作固定为单行“Safari 打开”，并使用低饱和 Safari 紫；Chrome 动作使用 Chrome 蓝或中性状态色，窄行中不能因浏览器名称换行。
- 点击“查看”只在页匣中切换、展开并定位；“恢复整组”打开 Chrome 专属恢复预览。
- 搜索词高亮只改变字重，不使用荧光背景。
- 键盘上下键移动选择，Return 执行当前主动作，Escape 清空搜索；Return 在标签组行永远只“查看”。

## 6. Chrome 快照与 Safari 合集页面

快照列表使用资料柜式两栏布局：

- 左侧为按时间排列的快照索引。
- 同一标签组的多次保存显示为一个带低饱和组色标记的版本序列；主体直接打开最新版，独立箭头展开较早版本。
- 序列摘要显示最新版名称、版本数量、日期和网页数；展开后的旧版本使用缩进与 1px 竖线表达层级，不增加卡片或重阴影。
- 选择较早版本时只高亮对应子项；从搜索定位到较早版本时自动展开序列。
- 索引元数据明确标记“完整现场”或“标签组”，两种范围不依赖名称猜测。
- 右侧为选中快照的窗口、标签组和网页项。
- 快照标题用系统衬线体，时间和数量使用等宽体。
- 每个标签组标题右侧提供克制的“恢复整组”文字按钮，来源离线时显示“Chrome 未连接”并禁用。
- 恢复前使用 560px 原生预览面板：蓝色 Chrome 来源徽章、衬线组名、目标来源和三列数量摘要依次显示；“组内网页 / 当前已打开 / 将新建”不依赖颜色表达。
- 当前存在相同网址时显示克制的浅黄色提示，明确为保留语境仍会全部新建；安全边界使用低饱和 Chrome 蓝色，说明只组合本次新建标签。
- 底部永久显示短时内存提示，取消与最终恢复并列；浅色和深色均不使用渐变、重阴影或玻璃效果。
- 执行后在内容区右上角保留 380px Chrome 恢复回执：顶部同时显示 Chrome 图标、文字来源与“恢复回执”，正文用衬线标题和三列平直指标呈现“已创建 / 应创建 / 标签组”。
- 完整成功、部分完成、失败与超时分别使用低饱和绿、黄、红和黄作辅助语义，但状态图标、标题和文字必须独立表达结果，不能只靠颜色。
- 部分完成或超时的说明明确“先核对 Chrome、不会自动清理或重试”；回执只由恢复结果触发，不增加全屏遮挡、自动消失倒计时或无意义动画。
- Chrome 回执在 Safari 页面与 Safari 专属搜索中隐藏，返回 Chrome 后重新出现；它不会转换成 Safari 状态，也不会覆盖 Safari 的独立确认反馈。
- 普通操作提示采用同一规则：48px 紧凑平面容器，第一行使用 8px 等宽浏览器名称和 SF Symbol，第二行显示结果；浏览器来源色只作辅助。Chrome 提示不进入 Safari 页面或 Safari 专属搜索，Safari 提示亦然；“全部浏览器”搜索可以显示任一来源提示。
- 跨浏览器设置和资料操作沿用 40px 中性提示，不添加虚假的 Chrome 或 Safari 徽章。
- 选中快照后，标题旁直接显示低强调的“删除快照”按钮，避免把关键资料管理能力藏在更多菜单中。
- 删除前使用系统确认框显示快照名称和网页数量，并明确操作无法撤销、不会影响 Chrome。

Safari 合集复用同一资料柜骨架，但不复用 Chrome 语义：

- 页面标题、空状态、数量和删除确认统一使用“Safari 合集”。
- 索引只显示 Safari 记录，不显示 Chrome 版本序列；详情使用 Safari 紫色来源徽章。
- 网页集中显示在“合集网页”，不伪装成窗口或标签组。
- 主动作是“在 Safari 打开全部”，并在系统确认框展示网页数量；不显示“恢复整组”、Chrome 连接状态或 Chrome 恢复回执。

## 7. Safari 按需收纳页面

- 顶部显示 Safari 来源徽章、标题“Safari 按需收纳”和“0 常驻读取”，直接解释低内存取舍。
- 三步条以“在 Safari 选中目标组 → 读取当前窗口 → 核对后保存”说明操作，不把权限或技术名词放在首屏中心。
- 未读取时只保留一个明确主按钮；读取后切换为连续预览列表，显示顺序、标题、域名、当前页与跳过数量。
- 保存按钮在预览完成后出现，弹窗使用中性“命名本地副本”，不复用 Chrome 标签的安全说明。
- 页面底部永久说明不监测后续变化、不修改 Safari，合集与原标签组彼此独立。

## 8. 设置页面

设置只展示必要信息：

- Chrome 来源名称与连接状态。
- 本地数据目录。
- 三步连接准备：显示扩展文件、填写扩展标识、配置本地连接。
- 扩展、Native Messaging Host 的缺失、有效与损坏状态。
- 导入与导出入口。
- 本地资料区域把 Chrome 快照与 Safari 合集显示为两条独立记录，各自展示数量、说明和“单独导出”；完整导入与导出位于两条记录之后。
- 导入预览使用 600px 原生面板：文件摘要在上，Chrome 蓝色行与 Safari 紫色行各自可选，中间只用 1px 边框和低饱和底色建立边界。
- 冲突说明使用克制的浅黄色语义底色；底部持续显示将导入的数量，未选择来源时主按钮禁用。
- Safari 按需收纳说明与直接入口，明确无需 Safari 扩展、无需完整 Xcode、没有后台轮询。
- 永久可见的安全说明：不会自动关闭、移动、挂起或重组 Chrome、Safari 已有标签。

当前版本不提供主题、圆角、动画等纯装饰设置。

## 9. 动效与可访问性

- 首次出现使用 180–240ms 的轻微透明度和 6px 位移。
- 列表实时更新不播放入场动画，避免大量标签变化时闪烁。
- 按钮按下只做 0.98 缩放或系统原生按压反馈。
- 遵守“减少动态效果”和“减少透明度”系统设置。
- 所有交互具备键盘路径、清晰焦点和 VoiceOver 标签。
- 正文与背景至少满足 WCAG AA 对比度。
- 不以颜色作为唯一状态表达。

## 10. 应用图标

图标采用温暖骨白底色与深色索引柜轮廓，内部放置蓝、绿、黄三条短装订脊线。无渐变、无文字、无拟物阴影，在 16px 菜单栏与 1024px 应用图标下都能辨认。
