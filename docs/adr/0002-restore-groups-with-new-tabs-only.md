# 只用新建标签恢复完整分组

状态：已接受

日期：2026-08-07

## 背景

基础版本允许从快照打开单个网页，但用户手动关闭整个 Chrome 标签组后，无法一次恢复原组名、颜色和网页顺序。整组恢复需要使用 Chrome 的标签分组写 API，因此必须重新明确“不改动已有标签”的安全边界。

## 决策

新增严格白名单命令 `restoreGroup`：

1. 只有快照标签组标题栏的“恢复整组”可以发起。
2. 发起前显示组名和将打开的网页数量，并要求用户明确确认。
3. 来源必须仍在 30 秒新鲜度窗口内。
4. 扩展先校验组名、颜色和全部 `http/https` 网址。
5. 扩展按快照顺序创建后台标签，并只收集本次命令返回的标签标识。
6. `chrome.tabs.group` 只能接收这批新建标签标识；随后用 `chrome.tabGroups.update` 设置原组名和颜色。
7. 不关闭、移动、挂起、解除分组或重组任何已有标签。

静态检查限制分组写 API 的文件位置、调用数量和 `createdTabIds` 参数；Node 测试使用模拟 Chrome API 验证分组集合完全来自本次 `tabs.create` 返回值。

## 结果

- 用户形成“保存确认 → 手动关闭释放内存 → 搜索单页或恢复整组”的完整闭环。
- 扩展权限不增加，仍不申请 host、历史、书签、下载或无痕权限。
- Chrome API 在创建部分标签后失败时，已创建标签保持可见并报告失败；页匣不通过关闭标签做自动回滚。
- 开发与自动化验收继续只使用模拟数据，真实 Chrome 中的整组恢复必须单独手动验证。

## 与既有决策的关系

本决策扩展了 [ADR 0001](0001-native-app-with-read-only-chrome-bridge.md) 的命令白名单，但不改变其原生应用、极简扩展、本地数据和不操作已有标签的总体架构。
